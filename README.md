# angzarr-examples-rust

Example implementations demonstrating Angzarr event sourcing patterns in Rust. See the [Angzarr documentation](https://angzarr.io/) for more information.

The poker example is parked, not deleted: it was removed for its complexity
(owner, 2026-10-27, "at least for now") and may come back. Its last version
is at 59bd1b8e (`git checkout 59bd1b8e`); it was removed in aabe5e3. Blackjack
replaces it as the example. This repository holds the Rust side of the
blackjack example: the aggregates, sagas, process managers and
projections. The virtual players are Python. The spec (protos under
`proto/io/angzarr/examples/v1/`, Gherkin under `features/example/blackjack*/`)
lives in the [angzarr-project](https://github.com/angzarr-io/angzarr-project)
submodule; the submodule pin is the contract this repository implements.

## Crates

- `proto` (`examples-proto`) - the generated `io.angzarr.examples.v1` types
  (cards, table, player), read straight from the submodule's protos by
  prost-build in `proto/build.rs` (needs `protoc`).
- `table/agg` (`agg-table`) - the table aggregate's domain logic as pure
  functions with no framework dependency: the deterministic shoe
  (`cards.proto`), the CreateTable decision (TableCreated + ShoeShuffled),
  the appliers that fold those events into `TableState`, and `TableLogic`,
  the whole table behind one trait (one method per command and event) that
  a harness adapter delegates to. Tests sit next to
  each module in `*.test.rs` and cite the spec's EU ids.
- `table/policies` (`table-player-policies`) - the two policies between
  the table and the Python player bot as plain Rust traits
  (`TablePlayer`: TurnStarted to DecideMove; `PlayerTable`: MoveDecided to
  Hit, Stand or DoubleDown), no framework.
- `table/embedded` (`table-embedded`) - the table aggregate and both
  policies on angzarr-embedded (angzarr's in-app runtime): thin adapters
  in its markup (`#[aggregate]`, `#[policy]`) delegating to agg-table's
  `TableLogic` and table-player-policies. The adapters were generated by
  `angzarr scaffold rust` (angzarr-cli) and every hand edit is marked
  `HAND-EDIT`. The scaffold cannot read the spec's protos as they are (they
  name a projector and components in other files), so it was run on a
  copy with those references removed:

  ```bash
  # in a scratch copy of angzarr-project/proto, drop from table.proto and
  # policies.proto every (event) option naming LedgerProjection,
  # TableBuyInPolicy or TableWalletPolicy, and the TableWalletPolicy message
  angzarr scaffold rust -I <copy> --src table/embedded/src \
    io/angzarr/examples/v1/table.proto \
    io/angzarr/examples/v1/player.proto \
    io/angzarr/examples/v1/policies.proto
  ```

  angzarr-embedded is pinned by hash in the workspace `Cargo.toml`.
  `tests/remote_player.rs` plays a whole hand against the Python player bot
  (examples-python), hosted as a child process by angzarr-embedded-host;
  it is ignored by default (it needs `uv`):

  ```bash
  ANGZARR_PLAYER_DIR=<examples-python>/player \
    cargo test -p table-embedded --test remote_player -- --ignored
  ```
- `tools/archlint` - the module-layering linter for `archlint.toml`.

## Development

### Setup

Install git hooks (requires [lefthook](https://github.com/evilmartians/lefthook)):

```bash
lefthook install
```

This configures a pre-commit hook that auto-formats Rust sources before each commit.

### Recipes

```bash
just -l              # List all available recipes
just build           # Build the workspace
just test            # Run tests
just fmt             # Check formatting
just fmt-fix         # Auto-format code
just lint            # Clippy, warnings denied
just archlint        # Module layering rules (archlint.toml)
just mutation-test   # cargo-mutants over the aggregate, policies and embedded host
just mutation-push   # pre-push: the same, over what a push adds (stdin: git's pushed refs)
just up              # Kind cluster with coordinators + infrastructure
```
